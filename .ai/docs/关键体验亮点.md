## 一、现有导购 AI 大致发展到什么程度

从公开资料看，主流电商平台的 AI 导购已经不再只是“搜索框升级”，而是在向“对话式购物助手”和“购物 Agent”演进。

| 平台 / 产品 | 已公开能力 | 对本项目的启发 |
| --- | --- | --- |
| Amazon Rufus / Alexa for Shopping | 基于商品目录、评论、问答和外部信息回答购物问题，支持商品咨询、对比、推荐、评论摘要、价格历史等购物决策能力。 | 说明导购 AI 的核心价值已经从“找商品”扩展到“帮用户做决策”。 |
| Walmart Sparky | 支持对话式理解需求、评论总结、场景推荐、计划、对比和购买辅助，并规划扩展到复购、服务预订、多模态输入。 | 说明下一代导购体验会把推荐、计划、购买和生活服务连接起来。 |
| 淘宝 AI 万能搜 / AI 助手 / AI 帮我挑 | 支持自然语言购物问题，生成融合文字、商品、图片、视频的答案报告；通过多轮对话帮助用户明确需求，并给出商品推荐、攻略、优惠咨询、口碑评测等内容。 | 说明国内电商导购 AI 正在解决“选择困难”和“攻略分散”的问题。 |
| 京东京言 / 京东 AI 购 | 公开报道中提到品类咨询、送礼助手、商品对比、评价总结、价格对比、AI 试穿等能力。 | 说明导购 AI 正在和更完整的履约、生活服务、即时购买入口结合。 |

这些产品已经证明了一个趋势：**用户不再只需要搜索结果列表，而是需要一个能理解需求、压缩信息、辅助决策、连接交易动作的购物助手。**

但同时，学术评测和实际体验也说明，购物 Agent 的难点并没有完全解决。比如 ShoppingComp 这类面向购物 Agent 的评测指出，真实购物任务不仅要求商品检索准确，还要求报告生成可靠、安全风险判断正确。也就是说，导购 AI 的竞争重点不只是“能说”，还包括：

- 能不能拿到真实商品、价格、库存、评价、优惠、订单数据。
- 能不能把推荐理由和商品事实绑定起来。
- 能不能避免编造商品、误用优惠、误触发交易动作。
- 能不能把多轮对话、图片、语音、购物车、订单等流程真正打通。
- 能不能被运营和开发人员追踪、调试、评估和持续优化。

## 二、本项目当前已经实现的导购能力

本项目不是一个孤立的 AI 聊天 Demo，而是一个带 Android 原生前端、Go 后端、商品库、购物车、订单、优惠券、评价、知识库、语音和图片检索的电商 AI 导购系统。

### 1. Android 端已落地的体验

Android 端已经拆分为多 Activity + 按模块分包结构，核心页面包括：

- AI 导购聊天页
- 商品列表页
- 商品详情页
- 购物车页
- 结算页
- 订单页
- 优惠券页
- 登录注册页
- 账号管理页
- 设置、帮助、关于、高级设置页

聊天页支持：

- 文本输入
- 语音输入
- 图片 / 文件附件上传
- SSE 流式接收 AI 回复
- 实时思考过程面板
- 商品卡片、对比表、购物车卡片、订单卡片、优惠券卡片、评价摘要卡片
- 推荐追问
- 历史会话列表、搜索、置顶、删除、恢复
- 从 AI 回复中的商品卡片直接进入详情或加入购物车

### 2. 后端 Agent 已落地的能力

后端 Agent 主链路包括：

```text
用户消息
  -> 风险检查
  -> 附件和图片信息归一化
  -> 会话短期记忆检索
  -> 一级路由：guide / non_guide
  -> 子意图识别：P1-P6 导购意图或购物车/订单/优惠券/评价等服务意图
  -> ReAct 工具调用
  -> 商品 / 知识库 / 图片 / 购物车 / 订单 / 优惠券 / 评价工具执行
  -> SSE 输出思考过程、正文、结构化卡片和追问
  -> Trace 记录，供后台排查
```

后端已支持的关键工具包括：

- 商品搜索：`search_products`
- 图片搜同款：`search_image_products`
- 知识库搜索：`search_knowledge`
- 购物车读取、加购、修改、删除
- 结算下单
- 订单查询、支付、取消、确认收货
- 优惠券查询、领取、优惠试算
- 商品评价查询和创建

同时，系统还支持：

- Nacos 动态配置
- Prompt 配置和发布
- Agent Run Trace
- 意图评测、RAG 评测、图片搜索评测
- 商家文档接入和非结构化知识入库
- 商品、订单、促销、评价、商家等后台管理 API

## 三、相比常见导购 AI 的关键体验亮点

### 亮点 1：不是“回答式导购”，而是“可执行的购物闭环”

很多导购 AI 的体验重点是回答问题、推荐商品、总结评论或给出购买建议。它们可以帮助用户做决策，但在演示或独立系统中，经常停留在“说得对不对”这一层。

本项目的亮点是：AI 回复可以继续连接真实电商动作。

用户可以从一句自然语言需求开始：

```text
我想买一款适合油皮、价格别太贵的洗面奶
```

然后系统可以完成：

```text
理解需求
  -> 检索商品
  -> 生成推荐理由
  -> 展示商品卡片
  -> 用户追问对比
  -> 用户选择某个商品
  -> 加入购物车
  -> 进入购物车
  -> 优惠试算
  -> 结算下单
  -> 查看订单
  -> 支付 / 确认收货 / 评价
```

这让 AI 导购不只是“消费建议工具”，而是进入了完整购物链路。

### 亮点 2：思考过程实时可见，降低黑盒感

现有很多导购 AI 只给最终结果，用户并不知道系统到底是在理解需求、搜索商品、总结评价，还是直接生成了一段看起来合理的话。

本项目在 Android 端专门实现了实时思考面板，后端通过 SSE 输出：

- 分析用户需求
- 查询商品与资料
- 总结答案

前端会在用户发送请求后展开思考页面，实时展示后端流式返回的阶段内容；当正式回答开始后，思考页面自动收起，并保存为历史消息的一部分。

这个设计的体验价值是：

- 用户知道 AI 当前正在做什么，不会误以为卡住。
- 用户能感受到导购回答是经过检索和分析的。
- 演示时可以清楚展示 Agent 的工作过程，而不是只展示一段最终文案。
- 后续可以把“思考过程”进一步扩展为更可控的解释层，例如展示筛选条件、排除理由、参考知识来源。

### 亮点 3：结构化购物 UI，而不是纯文本聊天

导购 AI 如果只输出自然语言，用户仍然需要自己从文字里提取商品、价格、优缺点和下一步操作。

本项目把 AI 输出拆成两类：

- `text_delta`：流式正文
- `block_delta`：结构化购物卡片

Android 端可以渲染：

- 商品卡片
- 商品对比表
- 引用来源卡片
- 购物车状态卡片
- 订单摘要卡片
- 优惠明细卡片
- 优惠券卡片
- 评价摘要卡片
- 售后规则卡片
- 页面跳转操作卡片
- 推荐追问按钮

这让导购回答从“聊天内容”变成了“可操作的购物界面”。用户不用复制商品名再搜索，也不用自己找入口，能直接点击商品、加购、去购物车、看订单或领券。

### 亮点 4：多模态入口完整覆盖文字、图片和语音

主流导购 AI 正在向多模态发展，比如图片找同款、语音购物、自然语言搜索等。本项目已经在演示系统内把这些入口连起来：

- 文字：用户直接输入自然语言购物需求。
- 图片：用户上传图片后，后端可通过图片向量检索相似商品。
- 语音：Android 端支持讯飞实时语音识别，同时保留 Android 系统语音识别兜底。
- 附件：前端支持上传图片 / 文件，后端统一管理文件和对象存储信息。

因此，用户可以用更接近真实购物的方式表达需求：

```text
拍一张图：帮我找类似这件外套
语音说：帮我挑一款送妈妈的生日礼物，预算三百以内
文字追问：第二个再便宜点有没有？
```

这种体验比单一文本聊天更接近日常购物场景。

### 亮点 5：导购意图和服务意图分流，避免 AI 乱做动作

一个常见风险是：AI 看起来会聊天，但一旦接入购物车和订单，就可能把推荐、加购、结算混在一起，导致误操作。

本项目后端先做一级路由：

- `guide`：选品、对比、搭配、场景方案、商品详情、图片找同款。
- `non_guide`：购物车、订单、优惠券、评价、售后、账号、导航、闲聊等。

然后再细分子意图，并为每个意图配置不同工具权限。

例如：

- 导购意图可以搜索商品和知识库，但默认禁用加购、结算等动作。
- 加购意图必须有明确商品 ID，不能凭空猜测。
- 结算意图必须先读取购物车，并基于选中商品创建订单。
- 订单动作必须明确订单 ID。
- 图片检索只能说明“相似商品 / 同款候选”，不能冒充已经识别出真实品牌型号。

这个设计让 AI 的能力边界更清楚，也让交易动作更安全。

### 亮点 6：推荐结果有事实约束，减少“编商品”

导购 AI 最容易出现的问题是：模型生成了一个听起来合理的商品，却不一定真实存在于当前商品库中。

本项目在后端做了多层约束：

- 商品推荐必须先调用 `search_products`。
- 商品卡片只能来自工具返回且相关性通过的商品 ID。
- `search_products` 返回弱相关或无匹配时，不能把候选商品当作正式推荐挂出来。
- 最终回答中的商品卡片会经过白名单过滤，拦截模型编造或弱相关商品。
- 工具结果、候选商品、剔除商品和相关性原因会写入 Trace。

这使得 AI 推荐更像“基于当前商品库的可购买建议”，而不是“语言模型自由发挥的购物清单”。

### 亮点 7：任务型会话管理，适合真实购物决策

本项目不是把所有聊天塞进一条长对话，而是把每段会话当成一个购物任务。

用户可以：

- 新建会话
- 查看历史会话
- 搜索历史会话
- 置顶重要会话
- 删除会话
- 继续之前的购物任务

后端还支持同一会话内的短期记忆：当用户说“刚才那个”“第二个”“继续推荐”“加入购物车”时，系统会在当前会话范围内寻找相关上下文和商品引用。

这个设计兼顾了两点：

- 同一购物任务内保持连续。
- 不同购物任务之间默认隔离，避免旧需求污染新需求。

### 亮点 8：AI 导购和传统电商页面打通

很多 AI 导购 Demo 只有聊天框，传统电商页面则是另一套系统。用户从 AI 推荐跳到商品、购物车、订单时，体验容易断裂。

本项目的 Android 端已经把 AI 导购和传统电商页面打通：

```text
AI 聊天页
  -> 商品列表
  -> 商品详情
  -> 购物车
  -> 结算页
  -> 订单页
  -> 优惠券页
  -> 账号页
```

AI 负责降低决策成本，传统页面负责承载浏览、确认和交易。两者不是替代关系，而是互相配合。

### 亮点 9：运营和开发可追踪，不是不可调试的黑盒

本项目后端保留了 Agent Run 和 Trace 体系，可以记录：

- 意图路由结果
- 使用的模型
- 工具调用参数
- 工具返回结果
- 商品候选和剔除原因
- 结构化卡片
- 最终回答
- 追问生成
- 错误和耗时

同时，系统支持 Nacos 动态配置和 Prompt 配置，不需要每次改 Prompt 都重新发布后端代码。

这对真实导购系统很重要。因为导购 AI 的问题往往不是“模型完全不会”，而是需要持续排查：

- 是意图分错了？
- 是检索召回不准？
- 是工具权限给错了？
- 是商品数据不完整？
- 是模型没有使用工具结果？
- 是前端卡片渲染不完整？

有 Trace 和动态配置后，系统具备持续迭代能力。

### 亮点 10：同时覆盖用户侧、商家侧和平台侧能力

本项目不只做用户端导购，还在后端保留了商家和平台管理能力：

- 商家商品管理
- 商家订单管理
- 商家促销管理
- 商家评价处理
- 商家文档接入
- 非结构化知识入库
- 管理员商品、订单、商家、促销、评价管理
- 管理员 Prompt、配置、向量状态、评测报告管理

这意味着 AI 导购不是孤立在用户端，而是可以和商家知识、平台运营、商品治理、促销策略一起迭代。

## 四、适合演示时重点展示的体验路径

### 路径 1：从模糊需求到商品推荐

演示话术：

```text
我想买一款适合油皮、平价一点的洗面奶。
```

重点展示：

- AI 展开思考过程
- 分析需求
- 查询商品与资料
- 输出推荐理由
- 展示商品卡片
- 生成后续追问

### 路径 2：从商品推荐到连续追问

演示话术：

```text
第二个和第三个对比一下。
```

重点展示：

- 同一会话内短期记忆
- 商品对比表
- 推荐理由不是孤立文本，而是围绕前一轮商品继续展开

### 路径 3：从 AI 决策到真实加购

演示话术：

```text
把第二个加入购物车。
```

重点展示：

- 系统能识别商品指代
- 加购不是口头回复，而是真实写入购物车
- 前端展示购物车状态卡片
- 用户可以继续进入购物车页

### 路径 4：图片找同款

演示动作：

```text
上传一张商品图片，然后提问：帮我找相似商品。
```

重点展示：

- 附件上传
- 图片向量检索
- AI 返回相似商品候选
- 商品卡片可点击进入详情

### 路径 5：语音导购

演示动作：

```text
按住语音按钮，说：帮我挑一款送妈妈的生日礼物，预算三百以内。
```

重点展示：

- 讯飞实时语音识别
- 识别内容进入输入框
- AI 按自然语言需求完成导购

### 路径 6：购物车、优惠、结算、订单闭环

演示动作：

```text
去购物车
查看优惠
结算
查看订单
支付 / 确认收货 / 评价
```

重点展示：

- AI 导购和传统电商页面打通
- 优惠券、优惠试算、结算、订单状态不是静态展示，而是真实后端业务状态

### 路径 7：后台 Trace 和配置能力

演示动作：

```text
打开某次 Agent Run 的 Trace。
```

重点展示：

- 看到路由、工具调用、商品候选、最终回答
- 能解释 AI 为什么这么推荐
- 能通过配置中心和 Prompt 管理继续优化导购效果

## 五、实事求是的边界说明

相比 Amazon、淘宝、京东、Walmart 这类成熟平台，本项目不具备它们的商品规模、用户行为数据、真实履约体系、广告系统和长期个性化积累。

因此，本项目的亮点不是“商品规模超过大平台”，而是：

1. **在一个自建演示系统里，把 AI 导购和真实电商链路打通。**
2. **把思考过程、结构化卡片、工具权限、交易安全、Trace 调试做成了可展示的产品体验。**
3. **能清楚说明一个导购 Agent 从理解需求到调用工具再到落地交易的完整过程。**
4. **具备后续扩展到商家知识库、平台运营、评测体系和动态 Prompt 优化的基础。**

## 六、一句话总结

本项目的关键体验亮点是：

**它不是一个只会推荐商品的聊天机器人，而是一个能看得见思考过程、能调用真实商品和知识库、能展示结构化购物卡片、能接入图片和语音、能完成购物车和订单闭环、还能被后台追踪和持续优化的电商 AI 导购系统。**
