# 图片搜索、风控与浏览器采集规划 v1

更新时间：2026-05-25

## 背景

当前项目已经有文本导购 Agent、商品搜索、RAG、Milvus 文本向量和基础质量测评。下一阶段需要补齐三类能力：

1. 图片匹配、图片搜索。
2. 风控板块，命中风控词时直接返回。
3. 用浏览器自动化脚本采集商品、商家、评价、商品详情等数据。

这三类能力都应服务于现有商品库、Agent 工具链路和管理员可观测体系。

## 总体实施顺序

1. 先做风控。
   - 风控是所有用户输入、图片输入、采集入库前的统一安全门。
   - 命中后不进入 Agent、不调用模型、不调用工具。
2. 再做图片匹配/图片搜索。
   - 图片搜索需要接商品库、图片向量和 Agent 工具。
   - 风控可先保护图片 URL、图片 OCR/描述文本和用户补充文本。
3. 最后做浏览器自动化采集。
   - 采集结果需要经过清洗、风控、入库、索引和测评。
   - 目标网站需要选择公开、结构稳定、低反爬、低法律风险的站点。

## 1. 图片匹配 / 图片搜索

### 1.1 目标

用户上传商品图或提供图片 URL 后，系统能返回相似商品或明确提示未找到，不能伪造识别结果。

典型场景：

- “帮我找这张图里的同款”
- “有没有类似这双鞋的商品”
- “按这张图找黑色外套”
- 用户上传无关图片时提示未找到相似商品

### 1.2 后端链路

新增图片输入处理链路：

1. 接收图片 URL 或上传后的附件 URL。
2. 校验：
   - 文件大小。
   - MIME 类型。
   - 图片格式。
   - URL 白名单/超时/重定向限制。
3. 下载或读取图片。
4. 原图写入 MinIO，得到内部 `object_key` 和可控访问 URL。
5. 基于 MinIO 对象生成图片 embedding。
6. Milvus 图片向量召回。
7. RDS 商品状态、库存、类目过滤。
8. 重排并返回商品卡片。

### 1.3 文件与图片存储

图片和文件统一存 MinIO，不直接依赖外部图片 URL 作为长期数据源。

建议 bucket：

```text
xzxg-shop-assets
```

对象 key 规划：

```text
uploads/{account_id}/{yyyy}/{mm}/{uuid}.{ext}
products/{product_id}/main/{image_id}.{ext}
products/{product_id}/detail/{image_id}.{ext}
reviews/{review_id}/{image_id}.{ext}
crawler/{crawl_batch_id}/{source_site}/{image_id}.{ext}
```

使用原则：

1. 用户上传图片、爬虫采集图片、商品主图和详情图都先落 MinIO。
2. MySQL 只保存 `object_key`、访问 URL、hash、mime、size、来源信息。
3. 图片 embedding 使用 MinIO 对象生成，避免外链失效导致无法重建索引。
4. 对外展示可使用后端签名 URL 或静态代理 URL，避免直接暴露 MinIO 内部凭据。
5. 下载外部图片时限制大小、超时、重定向次数和 content-type。

建议新增表或字段：

| 字段 | 说明 |
| --- | --- |
| `object_key` | MinIO 对象路径 |
| `source_url` | 原始外链，可为空 |
| `content_hash` | 去重和追踪 |
| `mime_type` | 文件类型 |
| `size_bytes` | 文件大小 |
| `storage_provider` | 默认 `minio` |

### 1.4 向量库设计

新增 Milvus collection：

```text
product_image_vectors
```

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `image_id` | string | 图片向量主键 |
| `product_id` | string | 商品 ID |
| `sku_id` | string | SKU ID，可为空 |
| `object_key` | string | MinIO 对象路径 |
| `image_url` | string | 可访问 URL 或签名 URL |
| `image_type` | string | main/detail/review/crawled |
| `embedding` | vector | 图片 embedding |
| `updated_at` | int64 | 更新时间戳 |

商品侧图片向量来源：

- 商品主图。
- 商品详情图。
- 爬虫采集图片。
- 后续可扩展评价晒图。

### 1.5 模型与服务选择

优先接当前模型供应商的多模态 embedding 能力，便于复用 API key、限流和日志。

候选：

- DashScope 多模态 embedding。
- CLIP/OpenCLIP 自部署。
- 其他支持 image embedding 的 OpenAI 兼容服务。

MVP 原则：

1. 先接一个可用 embedding 服务。
2. 图片向量和文本向量分 collection。
3. 图片搜索失败时明确降级，不用文本规则假装识别图片。

### 1.6 Agent 工具

新增工具：

```json
{
  "type": "tool_call",
  "tool": "search_products_by_image",
  "arguments": {
    "image_url": "https://example.com/a.jpg",
    "object_key": "uploads/acct_001/2026/05/xxx.jpg",
    "query": "可选的补充文本",
    "limit": 5
  }
}
```

Observation：

```json
{
  "tool": "search_products_by_image",
  "ok": true,
  "relevance_status": "ok",
  "message": "找到 3 个相似商品",
  "product_ids": ["p_001", "p_002"],
  "result": {
    "items": [],
    "image_match": {
      "top_score": 0.82,
      "model": "image-embedding-model"
    }
  }
}
```

与现有挂品保护一致：

- 只有 `relevance_status=ok` 的结果允许进入 final_allowed_product_ids。
- `weak/no_match` 不允许挂品。

```json
  "object_key": "uploads/acct_001/2026/05/xxx.jpg",
```


### 1.8 测评

新增数据集：

```text
quality/data/eval/image_search_cases.jsonl
```

Case 字段：

```json
{
  "id": "image_001",
  "image_url": "https://...",
  "object_key": "products/p_001/main/a.jpg",
  "query": "可选补充文本",
  "expected_product_ids": ["p_001"],
  "expected_category_ids": ["c_shoes"],
  "expected_relevance_status": "ok"
}
```

核心指标：

| 指标 | 目标 |
| --- | --- |
| `image_recall_hit_rate@5` | 相似商品 Top5 命中率 |
| `image_no_match_accuracy` | 无关图正确 no_match 比例 |
| `image_latency_p95` | 图片搜索 P95 延迟 |
| `image_total_duration_ms_p95` | 图片搜索端到端 P95 耗时 |
| `image_download_duration_ms_p95` | 外链下载或 MinIO 读取 P95 耗时 |
| `image_upload_duration_ms_p95` | 上传并写入 MinIO P95 耗时 |
| `image_embedding_duration_ms_p95` | 图片 embedding P95 耗时 |
| `image_vector_search_duration_ms_p95` | Milvus 图片召回 P95 耗时 |
| `image_rerank_duration_ms_p95` | 图片搜索重排 P95 耗时 |
| `invalid_image_block_rate` | 非法图片拦截比例 |

图片处理可能显著拉长响应时间，因此测评报告必须拆分耗时：

```json
{
  "id": "image_001",
  "durations": {
    "total_ms": 1850,
    "download_ms": 120,
    "minio_put_ms": 80,
    "embedding_ms": 1300,
    "vector_search_ms": 90,
    "rerank_ms": 40
  }
}
```

验收阈值建议：

- 图片搜索 `total_ms p95 <= 3000ms`。
- 已有 `object_key` 的图片搜索 `total_ms p95 <= 2200ms`。
- embedding 阶段单独统计，超过阈值时可考虑异步预索引或缓存。

## 2. 风控板块

### 2.1 目标

所有用户输入先过风控。命中风险词或风险模式后，直接返回固定安全响应，不进入 Agent、不调用模型、不调用工具。

覆盖入口：

- 文本 Agent 输入。
- 图片 URL、附件名称、图片 OCR/描述文本。
- 搜索 query。
- 爬虫采集入库内容。

### 2.2 风控类型

MVP 先做规则风控：

| 类型 | 说明 |
| --- | --- |
| `banned_goods` | 违禁商品、管制品、非法交易 |
| `privacy` | 手机号、身份证、地址等敏感隐私请求 |
| `prompt_injection` | 提示词注入、越权读取系统 prompt |
| `abuse` | 辱骂、骚扰、仇恨内容 |
| `fraud` | 诈骗、套现、虚假交易 |
| `security` | 攻击脚本、爬取账号、绕过风控 |

### 2.3 配置来源

新增 Nacos 配置：

```text
xzxg-shop-risk-config.json
```

示例：

```json
{
  "rules": [
    {
      "rule_id": "risk_banned_goods_001",
      "type": "banned_goods",
      "severity": "block",
      "patterns": ["违禁词1", "违禁词2"],
      "message": "该请求涉及平台禁止内容，无法继续处理。"
    }
  ]
}
```

后续管理员页面可以支持维护规则、启停规则和查看命中记录。

### 2.4 后端模块

新增包：

```text
backend/src/risk
```

核心类型：

```go
type Rule struct {
  RuleID   string
  Type     string
  Severity string
  Patterns []string
  Message  string
}

type Result struct {
  Hit      bool
  RuleID   string
  Type     string
  Severity string
  Message  string
}
```

核心接口：

```go
type Checker interface {
  CheckText(ctx context.Context, text string) Result
}
```

### 2.5 Agent 接入

在 `/agent/sessions/{id}/messages:stream` 创建 run 后、planner 前执行：

1. `risk.CheckText(message.Content)`。
2. 命中 block：
   - SSE 输出 `text_delta` 固定话术。
   - SSE 输出 `warning` block。
   - trace 写 `risk.blocked`。
   - run 标记 completed。
3. 未命中才进入 planner 和 ReAct。

返回示例：

```json
{
  "type": "warning",
  "code": "risk_blocked",
  "message": "该请求涉及平台禁止内容，无法继续处理。"
}
```

### 2.6 Trace 与落库

Trace event：

```text
stage=risk
event_type=blocked|passed
```

metadata：

```json
{
  "hit": true,
  "rule_id": "risk_banned_goods_001",
  "risk_type": "banned_goods",
  "severity": "block"
}
```

不建议在 trace 中完整记录敏感原文。可记录摘要、hash 和截断文本。

可选新增表：

```text
risk_events
```

字段：

- `risk_event_id`
- `run_id`
- `account_id`
- `rule_id`
- `risk_type`
- `severity`
- `text_hash`
- `created_at`

### 2.7 测评

新增数据集：

```text
quality/data/eval/risk_cases.jsonl
```

Case：

```json
{
  "id": "risk_001",
  "input": "包含风控词的请求",
  "expected_blocked": true,
  "expected_type": "banned_goods"

```

| 指标 | 目标 |
| --- | --- |

| `risk_model_call_leak_rate` | 命中风控后仍调用模型比例，目标 0 |

## 3. 浏览器自动化采集

### 3.1 目标

用 Playwright 自动化采集商品、商家、评价、商品详情等信息，生成结构化数据，入 MySQL 并进入 RAG/向量索引。

### 3.2 站点选择原则

优先选择：

- 页面公开可访问。
- 结构稳定。
- 不要求登录。
- 不强依赖复杂反爬。
- 采集量小，作为测试和演示数据。
- 遵守 robots、站点条款和合理访问频率。

第一版不要碰强反爬或需要登录的大站。可以选择公开电商样例站、品牌官网公开商品页、或专门用于爬虫练习的商品站点。

### 3.3 采集内容

商品：

- 商品标题。
- 品牌。
- 价格。
- 图片 URL。
- 类目。
- 商品详情 URL。
- 参数规格。
- 详情描述。

商家：

- 商家名。
- 商家介绍。
- 服务信息。

评价：

- 评分。
- 评价内容。
- 评价时间。
- 评价标签。

采集元数据：

- `source_site`
- `source_url`
- `crawl_batch_id`
- `crawled_at`
- MinIO `object_key`
- 图片 `content_hash`

### 3.4 目录结构

```text
crawler/
  README.md
  package.json
  scripts/
    crawl_products.mjs
    crawl_detail.mjs
  output/
    products.jsonl
    merchants.jsonl
    reviews.jsonl
```

入库命令：

```text
backend/cmd/import-crawled-products
```

### 3.5 Playwright 采集流程

1. 打开列表页。
2. 解析商品卡片和详情 URL。
3. 控制并发和访问间隔。
4. 进入详情页。
5. 采集标题、价格、图片、规格、商家和评价。
6. 下载图片并写入 MinIO，JSONL 中保存 `object_key`、`source_url`、hash 和 mime。
7. 输出 JSONL。
8. 入库命令清洗、去重、写入 MySQL。
9. 触发商品文本向量和图片向量 bootstrap。

### 3.6 入库映射

| 采集字段 | 目标表 |
| --- | --- |
| 商品标题、价格、主图、品牌 | `products` |
| SKU/规格 | `product_skus` |
| 商家信息 | `merchants` |
| 评价 | `product_reviews` |
| 详情描述、规格、评价摘要 | `knowledge_documents` |
| 图片 object_key/source_url/hash | `product_images` 或商品图片字段 |

新增或复用字段：

- `source_url`
- `source_site`
- `crawl_batch_id`

如果现有表不加字段，MVP 可以先把来源信息写入 `tags_json` 或 knowledge document 内容中。后续再做 schema 迁移。

### 3.7 采集风控与质量控制

入库前执行：

1. 字段完整性校验。
2. URL 去重。
3. 图片 URL 可访问性校验。
4. 图片写入 MinIO 并计算 hash。
5. 风控词扫描。
6. 文本长度限制。
7. HTML 清洗。

不合格数据写入 rejected 文件：

```text
crawler/output/rejected.jsonl
```

### 3.8 测评

新增数据集：

```text
quality/data/eval/crawled_data_quality_cases.jsonl
```

指标：

| 指标 | 目标 |
| --- | --- |
| `crawl_success_rate` | 详情页采集成功率 |
| `required_field_complete_rate` | 必填字段完整率 |
| `duplicate_rate` | URL/商品重复率 |
| `import_success_rate` | 入库成功率 |
| `indexed_product_rate` | 入库后进入搜索/向量索引比例 |
| `crawl_page_duration_ms_p95` | 页面采集 P95 耗时 |
| `crawl_image_download_duration_ms_p95` | 图片下载 P95 耗时 |
| `crawl_minio_put_duration_ms_p95` | 图片写入 MinIO P95 耗时 |
| `crawl_import_duration_ms_p95` | 入库 P95 耗时 |
| `crawl_index_duration_ms_p95` | 文本/图片索引 P95 耗时 |

采集测评报告要区分“爬页面慢”“下载图片慢”“写 MinIO 慢”“入库慢”“建索引慢”，避免只看总耗时无法定位瓶颈。

## 4. 里程碑

### M1：风控 MVP

- Nacos 风控配置。
- 文本风险词拦截。
- Agent stream 前置拦截。
- trace 可查风险命中。
- `risk_cases.jsonl` 测评。

### M2：图片搜索 MVP

- MinIO 文件上传接口。
- 商品图片和上传图片统一落 MinIO。
- 图片 URL 搜索接口。
- 商品图片 embedding。
- Milvus `product_image_vectors`。
- Agent 工具 `search_products_by_image`。
- 图片搜索测评数据，包含处理时间分解。

### M3：采集 MVP

- Playwright 采集脚本。
- 采集图片写入 MinIO。
- JSONL 输出。
- 入库命令。
- 采集数据进入商品搜索和 RAG。
- 采集质量测评，包含页面、图片、入库、索引耗时。

## 5. 验收标准

1. 风控词请求不调用模型、不调用工具，直接返回风控提示。
2. 风控命中能在 trace 中看到规则 ID、风险类型和拦截状态。
3. 上传或传入商品图能召回相似商品。
4. 无关图片返回 no_match，不编造商品。
5. 爬虫能稳定采集至少 100 个商品及其商家、评价、详情数据。
6. 用户上传图片、商品图片、爬虫图片都能在 MinIO 中查到 object_key。
7. 采集数据能入库，并能被商品搜索、RAG 和图片搜索使用。
8. 图片搜索和采集测评报告都包含处理时间维度，能看出图片处理是否显著拉长响应。
9. 三类能力都有对应测评数据和报告入口。
