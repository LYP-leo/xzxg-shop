# 质量测评体系设计 v1

本文承接 `.ai/prd/质量体系需求_v1.md`，当前阶段只落地三类可运行测评，不做复杂 CI 门禁、LLM-as-judge 或线上质量平台。

## 1. 目标

质量体系先解决三个问题：

1. Agent 端到端回答是否合理。
2. Agent 意图分类是否符合预期。
3. RAG 召回是否能找回预期数据。

测评数据统一放在：

```text
quality/data/eval/
```

测评脚本放在：

```text
quality/evals/
```

测评输出统一为 JSON，放在：

```text
quality/reports/
```

`quality/reports/` 是运行产物，不提交 Git。

## 2. Agent 端到端测评

### 2.1 数据

文件：

```text
quality/data/eval/agent_e2e_queries.jsonl
```

格式：

```json
{"id":"agent_e2e_001","query":"推荐手机"}
```

支持附件：

```json
{"id":"agent_e2e_photo","query":"我拍照找同款","attachments":[{"type":"image","url":"https://example.com/test.jpg"}]}
```

### 2.2 执行

脚本：

```text
quality/evals/run_agent_e2e.mjs
```

命令：

```bash
node quality/evals/run_agent_e2e.mjs quality/data/eval/agent_e2e_queries.jsonl
```

### 2.3 输出

输出 JSON：

```json
{
  "type": "agent_e2e",
  "results": [
    {
      "id": "agent_e2e_001",
      "query": "推荐手机",
      "answer": "......",
      "blocks": [],
      "run_id": "run_xxx",
      "trace_id": "trace_xxx"
    }
  ]
}
```

当前阶段不自动打分，人工检查 `query-answer` 是否合理。

## 3. Agent 意图分类单项测评

### 3.1 数据

文件：

```text
quality/data/eval/intent_cases.jsonl
```

格式：

```json
{"id":"intent_001","query":"把手机加到购物车","expected_intent":"cart_add"}
```

### 3.2 后端接口

接口：

```text
POST /api/v1/eval/intent
```

请求：

```json
{"query":"把手机加到购物车"}
```

响应：

```json
{"query":"把手机加到购物车","intent":"cart_add"}
```

实现要求：

- 该接口调用线上 Agent 使用的同一个意图分类函数。
- 不允许测评接口复制一套独立分类逻辑，避免线上链路和测评链路漂移。
- 接口需要管理员鉴权。

### 3.3 执行

脚本：

```text
quality/evals/run_intent_eval.mjs
```

命令：

```bash
node quality/evals/run_intent_eval.mjs quality/data/eval/intent_cases.jsonl
```

### 3.4 输出

```json
{
  "type": "intent_classification",
  "total": 12,
  "correct": 10,
  "accuracy": 0.8333,
  "results": [
    {
      "id": "intent_001",
      "query": "把手机加到购物车",
      "intent": "cart_add",
      "expected_intent": "cart_add",
      "correct": true
    }
  ]
}
```

## 4. RAG 召回测评

### 4.1 数据

文件：

```text
quality/data/eval/rag_recall_cases.jsonl
```

格式：

```json
{"id":"rag_001","keyword":"X Phone 12 儿童抓拍","expected_recall":["ck_phone_001"]}
```

`expected_recall` 放预期召回的 chunk id。暂时没有标准答案的数据可以先写空数组，输出供人工看。

### 4.2 后端接口

接口：

```text
POST /api/v1/eval/rag
```

请求：

```json
{"keyword":"X Phone 12 儿童抓拍","top_k":5}
```

响应：

```json
{
  "keyword": "X Phone 12 儿童抓拍",
  "items": [
    {
      "chunkId": "ck_phone_001",
      "title": "X Phone 12 商品详情",
      "snippet": "......",
      "source": "mysql_seed"
    }
  ]
}
```

接口需要管理员鉴权。

### 4.3 执行

脚本：

```text
quality/evals/run_rag_recall_eval.mjs
```

命令：

```bash
node quality/evals/run_rag_recall_eval.mjs quality/data/eval/rag_recall_cases.jsonl
```

### 4.4 输出

```json
{
  "type": "rag_recall",
  "total": 4,
  "evaluated": 2,
  "hits": 2,
  "recall_case_hit_rate": 1,
  "results": [
    {
      "id": "rag_001",
      "keyword": "X Phone 12 儿童抓拍",
      "recalled": [],
      "expected_recall": ["ck_phone_001"],
      "hit": true
    }
  ]
}
```
