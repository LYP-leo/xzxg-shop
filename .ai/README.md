# .ai 文档目录说明

更新时间：2026-06-08

本目录用于沉淀小猪小狗 AI 导购项目的需求、接口契约、技术方案、测评数据、评审记录和 AI 协作 skill。后续新增文档应优先按这里的目录语义归档，避免 PRD、设计、问题记录和接口协议混在一起。

## 推荐阅读顺序

1. 评委快速体验：先看 `docs/部署与评委快速体验指南.md`，按公网环境或本地部署路线体验核心闭环。
2. 产品需求：从 `prd/需求_v1.md`、`prd/需求_v2.md`、`prd/需求_v3.md` 看产品范围演进。
3. 当前接口：从 `api/README.md` 进入，正式联调以 `api/API接口文档_v3.md` 和 `api/Agent输出协议_v1.md` 为准。
4. 当前技术主线：看 `tech/RAG设计_v5.md`、`tech/Agent框架设计_v2.md`、`tech/动态配置拆分与Prompt管理设计_v1.md`、`tech/质量测评体系设计_v1.md`。
5. 项目表达材料：看 `spec/business/项目亮点与方案梳理_v1.md`。
6. 代码评审：使用 `skill/xzxg-code-review/SKILL.md`。

## 目录职责

```text
.ai/
  api/             前后端接口、SSE、Agent 输出协议等可联调契约
  prd/             需求文档，只描述要解决什么问题和验收目标
  tech/            技术方案、实施规划、架构设计、调研报告
  spec/            跨模块规范、编码规范、系统级说明、答辩表达材料
  review/          代码检查、问题清单、历史评审记录
  test/            人工测试问题、bad case 记录
  test-data/       可机器读取的测试数据集
  local-prompts/   本地 OCR 或参考 Prompt 草稿，不作为线上唯一来源
  pics/            架构图、参考图、截图材料
  skill/           面向本仓库协作的 Codex/AI skill
```

## 文档类型边界

- `prd`：写“业务为什么需要、用户场景、验收标准”。不要写实现细节。
- `api`：写“请求、响应、鉴权、错误码、字段约束、兼容说明”。接口变更必须同步这里。
- `tech`：写“怎么实现、为什么这么设计、替代方案、风险与验证”。复杂改动先有设计。
- `spec`：写“长期稳定的规范和系统说明”，例如编码规范、架构分层、答辩技术亮点。
- `review`：写“一次检查发现了什么问题、风险等级、建议修复”。不要混入方案正文。
- `test-data`：只放测试数据，优先 JSONL/JSON/CSV 等机器可读格式。

## 当前版本基线

- API 基线：`api/API接口文档_v3.md`
- Agent 输出协议：`api/Agent输出协议_v1.md`
- Prompt 管理基线：Prompt 统一落库并通过管理员页面编辑，Nacos 不再作为 Prompt 主来源。
- Web 前端基线：React Web 用户端已废弃，React 只保留管理员/商家后台；用户端以 `android-native/` 为主。
- RAG 基线：商品搜索工具封装 RDS + 向量库召回、风控过滤、rerank、输出白名单校验。
