# 系统分层与职责 v1

更新时间：2026-06-08

## 总体分层

本项目可以分为八层：

```text
交互层
  -> 接入层
  -> 电商业务域
  -> Agent Runtime
  -> Agent 能力层
  -> Agent 工具层
  -> 管理与质量
  -> 数据与基础设施层
```

## 1. 交互层

职责：

- 承载用户和管理员的实际操作入口。
- 展示流式回答、商品卡片、思考过程、评价、图片和语音能力。
- 将用户行为转换为稳定的接口请求。

技术栈：

- Android 原生客户端：`android-native/`。
- React 管理后台：`frontend/`。

当前约定：

- Web 用户端已废弃，用户侧主入口是 Android 原生客户端。
- React 只保留管理员和商家后台能力。

## 2. 接入层

职责：

- HTTP API、SSE、鉴权、参数校验、错误响应。
- 将外部请求转换为内部业务调用。
- 统一注入 request_id、account、role、timeout。

技术栈：

- Go HTTP API：`backend/src/httpapi`。
- Token 鉴权和角色控制。

## 3. 电商业务域

职责：

- 商品、类目、SKU、库存、购物车、订单、优惠、评价、账号、商家等传统电商能力。
- 为 Agent tool 提供可执行、可追踪、可校验的业务接口。

技术栈：

- Go domain/store 层。
- MySQL 关系数据。

核心要求：

- 商品事实、价格、库存、订单状态必须来自业务域，不允许由模型编造。
- 写操作必须考虑鉴权、事务、幂等和审计。

## 4. Agent Runtime

职责：

- 承载单次用户请求的执行生命周期。
- 负责意图识别、Prompt 组装、工具选择、LLM 调用、流式输出、trace 记录。
- 控制并发、超时、错误降级和输出协议校验。

技术栈：

- Go Agent runtime：`backend/src/agent`。
- SSE 输出协议：`.ai/api/Agent输出协议_v1.md`。

## 5. Agent 能力层

职责：

- Prompt 模板。
- 意图分类。
- Query 改写。
- 记忆检索。
- 主 Agent ReAct。
- 非导购服务 Agent。
- 多模态理解和导购建议生成。

当前约定：

- Prompt 统一落库，通过管理员页面管理。
- Nacos 只保存模型、RAG 权重、外部服务等运行配置。
- 主 Agent 根据意图动态拼接可用工具、输出要求和安全约束。

## 6. Agent 工具层

职责：

- 把电商业务能力封装成模型可调用工具。
- 屏蔽 RDS、Milvus、MinIO、风控、订单、购物车等内部实现细节。
- 返回结构化结果，供 Agent 生成回答和前端展示。

典型工具：

- 商品搜索。
- 图片找同款。
- 加购。
- 下单。
- 查订单。
- 查优惠。
- 查评价。

核心要求：

- 工具返回的商品 ID 是 Agent 可挂品的唯一白名单。
- 商品召回需要经过风控过滤、状态过滤、相关性排序和输出校验。

## 7. 管理与质量

职责：

- 管理商品、商家、订单、账号、风控规则和 Prompt。
- 查看 Agent 全链路 trace，包括 LLM 输入 prompt、原始输出、tool 调用、召回片段和耗时。
- 管理测评数据集，运行 RAG、意图识别、Agent 端到端测评。

技术栈：

- React 管理后台。
- 后端 admin API。
- 测评报告和 trace 落库。

## 8. 数据与基础设施层

职责：

- 关系数据、向量数据、对象存储、动态配置、日志和部署中间件。

技术栈：

- MySQL：商品、订单、账号、trace、Prompt、测评结果。
- Milvus：文本和图片向量召回。
- MinIO：图片和文件对象存储。
- Nacos：运行配置。
- Docker：本地中间件部署。

## 分层原则

- 交互层不直接理解模型自由文本，应优先消费结构化协议。
- Agent 不直接写数据库，写操作通过 tool 调用业务域。
- RAG 和向量库细节封装在工具层，不暴露给前端。
- 管理后台只做配置和观测入口，不承载核心业务判断。
- 文档、接口、Prompt 和测评需要随代码一起维护。
