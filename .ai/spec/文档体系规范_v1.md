# 文档体系规范 v1

更新时间：2026-06-08

## 目标

让项目文档能回答三个问题：

1. 需求从哪里来。
2. 当前接口和协议以哪个版本为准。
3. 某个技术决策为什么这么做，以及历史替代方案是什么。

## 版本命名

推荐格式：

```text
主题_vN.md
```

示例：

- `API接口文档_v3.md`
- `RAG设计_v5.md`
- `质量测评体系设计_v1.md`

规则：

- `v1` 是第一个可独立阅读的版本，不要求等于第一个实现版本。
- 小修可以直接改当前版本。
- 需求方向、接口字段、协议结构、架构边界发生明显变化时，新开 `vN+1`。
- 历史版本不删除，当前基线在目录 README 中标明。

## 目录归档规则

### prd

放需求文档：

- 用户场景。
- 功能范围。
- 验收标准。
- 比赛新要求。

不要放具体代码实现、bug 排查日志。

### api

放接口契约：

- REST API。
- SSE 协议。
- Agent 输出协议。
- 前后端/客户端字段约定。

接口变更必须更新当前版本。

### tech

放技术方案：

- 架构设计。
- Agent/RAG/Prompt/测评/风控/多模态方案。
- 调研报告。
- 实施规划。

### spec

放长期规范：

- 编码规范。
- 文档规范。
- 系统分层。
- 答辩技术亮点。

### review

放检查和问题记录：

- 代码检查报告。
- Android 问题记录。
- bad case 分析。
- PR review 结果。

### test-data

放机器可读测评数据。人工问题记录放 `test/`。
