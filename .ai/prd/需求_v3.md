## 现在需要实现的功能

这一个版本主要做前端的技术栈迁移。

### 后端
1. 目前还没有实现聊天记录存储与恢复的功能，你需要实现这一功能
  - 对于未登录的用户，你只需要将聊天记录存储到本地
  - 对于已登录的用户，你需要将聊天记录存储到服务器
    - 已登录的用户仍旧需要将聊天记录存储到本地，只不过新增了个与服务器进行同步的功能
    - 用户进行聊天的时候，你需要选取合适的时机将用户的聊天记录与服务器进行同步

2. 对于用户管理功能，目前只能登陆，你需要实现：
  - 顾客 / 商家能够自主注册，自主修改密码
    - 调研一下手机注册和邮箱注册发送验证码是怎么实现的，能否接入我们的系统
  - 管理员能够管理用户

### 前端
1. 请你将所有功能由 Web 端迁移到 Android 端，技术选型由 React 换成 Android Studio 原生开发
  - 请你使用 Java 进行安卓原生开发
  - 对于 UI 界面，不可以直接照搬，你需要为安卓手机的界面重新设计，包括整个系统的交互逻辑都要改
    - 交互逻辑和页面的框架需要参考已有的 AI 聊天软件，例如：豆包、ChatGPT 等，并实现流式输出，
    - 每次打开软件的时候，都要开启一段新的聊天
    - 注意聊天记录的同步问题
  - 在参考已有 AI 聊天软件的同时，你需要考虑不同用户角色

2. 你需要将**顾客、商家、管理员三个角色的功能都迁移到 APP**，并根据合适的用户角色设计不同的页面功能
  - 这里说的 “顾客” 角色也就是已有的 “用户” 角色，为了表述更加清晰，我把 Web 端的 “用户” 改成 “顾客”
  - 既然每次打开 APP 都是一段新的对话，那么每次打开 APP 就是起到将历史会话记录同步到本地的作用
    - 你需要想好每次同步多少条历史回话，比如完整同步最近的 50 条，多余的就只同步会话标题与摘要
    - 同步过程中，先同步近期的，再同步久远的；先同步会话标题与摘要，再同步具体的会话内容，这样每同步好一条会话标题之后，就可以展示到 APP 当中，剩下的内容再慢慢同步
      - 同步的时候不要阻塞住，不要因为同步影响用户的其他功能
    - 如果用户的手机里已经存在要同步的历史回话，就不需要重复同步了，直接跳过同步步骤即可
  - 顾客、商家、管理员的功能和界面是不一样的，你需要分别设计
    - 对于所有用户，在未登录的情况下默认是顾客角色
