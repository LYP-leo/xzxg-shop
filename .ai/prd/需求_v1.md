# 电商 AI 导购系统 PRD v1

## 1. 背景与目标

本项目面向电商导购场景，构建一个打通“意图理解 - 智能咨询 - 决策辅助”的 AI Agent 系统。系统需要理解商品属性、营销规则、用户偏好与多轮对话上下文，通过 RAG 知识库和大模型 OpenAPI 输出专业、准确、可解释的导购建议，并在移动端提供接近“豆包”体验的流式交互、商品卡片实时渲染与多模态输入能力。

项目同时需要建设端到端质量评测与反馈闭环，通过典型导购场景的量化评估反哺 Prompt、知识库和检索策略迭代，验证该方案在模拟商业场景中的技术可行性、回答质量和交互体验。

## 2. 产品定位

产品名称：小猪小狗 AI 导购

产品形态：
- 移动端客户端：iOS / Android 原生应用，承载用户对话、图片输入、商品卡片、推荐理由与决策对比。
- 后端服务：提供文档上传、知识库构建、RAG 检索、Agent 编排、商品推荐、评测与反馈接口。
- 管理与评测后台：用于上传商品资料与营销文档、查看知识库状态、运行评测集、分析质量指标。

核心价值：
- 将传统“搜索商品信息”升级为“理解需求并辅助决策”。
- 通过专属知识库降低大模型幻觉，提高导购回答的专业性。
- 通过商品卡片和对比建议提升购买决策效率。
- 通过评测闭环持续优化 Prompt、检索和知识库质量。

## 3. 用户与场景

### 3.1 目标用户

消费者：
- 有明确购买需求，但不知道如何筛选商品。
- 在多个商品之间犹豫，需要对比优缺点、适用人群和性价比。
- 关注优惠活动、售后政策、使用限制等细节。

运营人员：
- 上传商品详情、营销活动、售后政策、导购话术等非结构化文档。
- 查看知识库构建状态和评测结果。
- 根据反馈优化商品资料与运营策略。

评测/研发人员：
- 构造典型导购评测集。
- 观察回答准确率、检索命中率、多轮对话稳定性。
- 调整 Prompt、检索参数、知识切片策略。

### 3.2 核心场景

1. 用户自然语言咨询：例如“预算 3000 以内，想买一台适合拍娃的手机，有什么推荐？”
2. 用户上传图片咨询：例如上传商品图、活动海报或已有购物车截图，让系统解析并给出建议。
3. 商品对比决策：例如“这两款扫地机器人哪个更适合养宠家庭？”
4. 优惠与规则解释：例如“满减、赠品和会员券能不能叠加？”
5. 多轮澄清与个性化推荐：系统主动追问预算、偏好、使用人群、约束条件后推荐。
6. 运营上传文档构建知识库：上传 PDF、Word、Markdown、图片 OCR 文档等商品与营销资料。
7. 质量评测闭环：运行标准问题集，统计回答准确率、引用依据、检索命中与多轮逻辑表现。

## 4. 产品目标与成功指标

### 4.1 MVP 目标

- 支持商品资料与营销文档上传，并完成向量化入库。
- 支持基于 RAG 的流式 AI 导购问答。
- 支持多轮对话中的用户意图识别、澄清追问、商品推荐和对比。
- 支持商品卡片在对话中实时渲染。
- 支持文本与图片输入，图片至少完成 OCR/视觉描述并进入 Agent 推理链路。
- 支持一套可重复运行的质量评测流程。

### 4.2 量化指标

回答质量：
- 典型导购问题回答准确率 >= 85%。
- 知识引用覆盖率 >= 80%。
- 禁止编造关键商品参数、价格、活动规则。

检索质量：
- Top-K 检索命中率 >= 85%。
- 关键商品属性召回率 >= 90%。
- 无关文档召回率逐步下降，可在评测报告中体现优化趋势。

交互体验：
- 首 token 响应时间 <= 2.5 秒。
- 流式输出稳定，无明显卡顿。
- 商品卡片可在答案生成过程中或答案生成后实时插入。

决策辅助：
- 至少支持推荐理由、适用人群、不适用情况、风险提示、替代方案。
- 至少支持 2 到 4 个商品横向对比。

评测闭环：
- 支持按评测集批量运行。
- 输出准确率、检索命中率、多轮任务完成率、失败样例。
- 支持将失败样例沉淀为 Prompt 或知识库优化建议。

## 5. 功能范围

### 5.1 客户端

#### 5.1.1 对话首页

功能要求：
- 展示 AI 导购会话列表与当前会话。
- 支持文本输入、图片上传、重新生成、停止生成。
- 支持流式渲染 AI 回复。
- 支持多轮上下文连续对话。
- 支持商品卡片、商品对比表、引用来源等结构化内容渲染。

验收标准：
- 用户发送问题后，客户端能逐字或分片显示 AI 回复。
- 回复中出现商品推荐时，可展示商品卡片，包括商品图、名称、价格、核心卖点、推荐理由、购买入口占位。
- 用户可继续追问，系统能引用前文约束。

#### 5.1.2 多模态输入

功能要求：
- 支持上传商品图片、活动海报、购物车截图。
- 图片输入进入后端视觉解析或 OCR 流程。
- 解析结果可作为上下文传给 Agent。
- 用户可结合图片继续提问。

验收标准：
- 上传图片后，系统能识别主要商品/文本信息。
- 对图片中的活动规则、商品名称或参数可进行解释或追问。

#### 5.1.3 商品卡片与对比组件

功能要求：
- 支持单商品推荐卡片。
- 支持多商品推荐列表。
- 支持商品横向对比表。
- 支持“为什么推荐”“适合/不适合谁”“主要差异”等解释字段。

验收标准：
- Agent 输出结构化商品数据后，客户端能稳定渲染。
- 卡片内容与自然语言答案一致。

### 5.2 后端服务

#### 5.2.1 文档上传与知识库构建

功能要求：
- 支持上传商品详情、营销文档、售后政策、FAQ、导购话术。
- 支持 PDF、Word、Markdown、TXT、HTML、图片 OCR 文档。
- 对文档进行解析、清洗、切片、Embedding、向量入库。
- 保存文档元数据：文档来源、商品 ID、类目、版本、上传时间、生效时间。
- 支持知识库重建与增量更新。

验收标准：
- 上传文档后可查看处理状态。
- 文档完成处理后可被 RAG 检索命中。
- 检索结果包含来源片段和元数据。

#### 5.2.2 RAG 检索服务

功能要求：
- 支持基于用户问题、会话上下文和意图的向量检索。
- 支持关键词/结构化过滤，例如类目、品牌、价格区间、商品 ID。
- 支持检索结果重排。
- 支持返回可引用的证据片段。

验收标准：
- 对商品参数、活动规则、售后政策类问题，回答必须基于检索证据。
- 当知识库无明确依据时，系统应提示“不确定”并建议用户补充信息或转人工。

#### 5.2.3 Agent 编排

功能要求：
- 识别用户意图：商品咨询、需求澄清、商品推荐、商品对比、活动解释、售后咨询、闲聊/兜底。
- 抽取用户约束：预算、品牌、类目、使用场景、送礼对象、性能偏好、禁忌条件。
- 根据意图选择工具：RAG 检索、商品检索、商品对比、图片解析、规则解释、评测日志记录。
- 支持多轮记忆，保留关键偏好和已推荐商品。
- 输出自然语言答案与结构化 UI 数据。

验收标准：
- 对信息不足的需求，Agent 优先追问关键约束，而不是直接泛泛推荐。
- 对冲突需求，Agent 能指出冲突并给出取舍建议。
- 对比类问题能输出差异、推荐结论和适用场景。

#### 5.2.4 商品服务

功能要求：
- 管理商品基础信息：名称、图片、类目、品牌、价格、库存状态、属性、标签。
- 支持商品查询、筛选、排序。
- 支持根据 Agent 推荐结果返回商品卡片数据。

验收标准：
- 推荐卡片数据来自商品服务，不直接依赖大模型自由生成。
- 商品价格、库存等动态信息可独立更新。

#### 5.2.5 评测与反馈服务

功能要求：
- 支持维护评测集：问题、标准答案、期望引用、期望商品、对话轮次、评分维度。
- 支持批量运行评测任务。
- 支持自动评分与人工复核。
- 支持记录用户反馈：点赞、点踩、原因、人工标注。
- 支持生成优化建议：Prompt 调整、知识缺口、切片问题、召回问题。

验收标准：
- 每次评测输出可追踪报告。
- 失败样例能关联到具体问题、检索结果和模型回答。

### 5.3 管理后台

功能要求：
- 文档上传与处理状态查看。
- 商品数据导入与维护。
- 知识库检索调试。
- Prompt 版本管理。
- 评测集管理与评测报告查看。

验收标准：
- 运营人员无需改代码即可上传资料并触发知识库更新。
- 研发人员可通过后台定位低质量回答原因。

## 6. 核心业务流程

### 6.1 知识库构建流程

1. 运营上传商品资料或营销文档。
2. 后端解析文档并提取文本、表格、图片 OCR 信息。
3. 文档清洗，去除噪声与重复内容。
4. 按商品、主题、语义边界进行切片。
5. 生成向量并写入向量数据库。
6. 保存文档与切片元数据。
7. 管理后台展示处理结果。

### 6.2 用户导购问答流程

1. 用户输入文本或图片。
2. 后端解析图片，合并文本上下文。
3. Agent 识别意图并抽取约束。
4. 如信息不足，先发起澄清问题。
5. 如信息充分，调用 RAG 与商品服务。
6. Agent 基于证据生成回答、推荐理由和结构化商品数据。
7. 客户端流式展示回答并渲染商品卡片。
8. 用户反馈进入评测与优化闭环。

### 6.3 评测优化流程

1. 维护典型导购问题集。
2. 批量运行问答与检索流程。
3. 记录检索结果、模型回答、引用证据、结构化输出。
4. 自动评分：准确率、召回率、引用覆盖、格式合规、多轮一致性。
5. 人工复核失败样例。
6. 生成优化项：补充文档、调整切片、优化 Prompt、调整检索参数。
7. 重新运行评测，比较指标变化。

## 7. 非功能需求

性能：
- 支持流式响应。
- 常规问答接口 P95 响应首包 <= 2.5 秒。
- 文档上传后异步处理，避免阻塞用户操作。

可靠性：
- 大模型调用失败时返回可理解的兜底提示。
- RAG 无结果时禁止编造。
- 商品服务异常时仍可回答知识咨询，但不展示商品卡片。

安全与合规：
- 上传文档需要校验类型和大小。
- 用户图片不用于无授权的长期训练。
- 日志中避免明文保存敏感个人信息。

可观测性：
- 记录每次对话的意图、检索 Query、Top-K 片段、模型版本、Prompt 版本、耗时。
- 支持按会话回放推理链路中的关键事件。

可扩展性：
- 大模型、Embedding 模型、向量数据库可替换。
- 客户端 UI 渲染协议与后端 Agent 输出解耦。

## 11. 风险与应对

大模型幻觉：
- 必须引入引用证据和“不确定”策略。
- 商品关键参数优先来自商品服务或知识库。

文档质量不稳定：
- 上传后做解析质量检查。
- 对低质量文档提示运营补充或修正。

检索不准：
- 引入结构化过滤、重排和评测集回归。
- 对商品属性类文档优化切片策略。

流式体验复杂：
- 后端采用标准 SSE 或 WebSocket 输出。
- 客户端按消息类型分层渲染文本、卡片、引用。

评测主观性强：
- 结合规则评分、大模型评分和人工复核。
- 保留可复现的评测输入、输出和模型版本。

## 12. 待确认问题

- 比赛是否要求必须同时实现 iOS 和 Android，还是任选一种原生端即可。
- 大模型 OpenAPI、Embedding 模型和向量数据库是否有指定供应商。
- 商品数据是由比赛方提供，还是需要团队自建模拟数据。
- 是否需要现场演示管理后台，还是以接口与报告形式展示即可。
- 对多模态能力的要求是 OCR 级别，还是需要视觉理解模型识别商品外观与场景。
