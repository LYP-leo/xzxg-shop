# Review 文档索引

更新时间：2026-06-08

`review/` 存放代码检查、问题清单、历史评审记录和专项排查结论。它和 `tech/` 的区别是：

- `tech/` 说明方案应该怎么做。
- `review/` 记录实际检查发现了什么问题，以及建议怎么改。

## 当前子目录

- `android/`：Android 原生客户端历史问题、代码检查和修复记录。

## 维护规则

1. 新 review 文档应写清检查对象、时间、结论、问题等级、文件位置和建议。
2. 不要把新的产品需求写进 `review/`，需求应放到 `prd/`。
3. 不要把完整技术方案写进 `review/`，方案应放到 `tech/`。
4. 已修复的问题可以保留历史记录，在后续文档或提交说明中标记修复状态。
